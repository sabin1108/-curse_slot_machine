## 요약 판정

현재 빌드는 **실제로 조작 가능한 15스테이지 시스템 MVP 시연 준비 완료(Ready)** 상태다.

대표 시드는 정해진 영상을 재생하거나 선택을 강제하는 스크립트가 아니다. 플레이어가 슬롯 회전, 릴 잠금, 재굴림, 결과 확정, 보상 선택, 상점 구매, 휴식 및 이벤트 선택을 직접 수행한다. 동일한 시드와 동일한 명령 순서가 동일한 결과를 만드는지 확인하기 위해 별도의 81개 명령 회귀 픽스처를 사용한다. 다른 선택을 하면 HP, 저주, 전투 결과, 보상과 빌드 경로가 달라진다.

단, 현재 판정은 **플레이 가능한 시스템 MVP**에 대한 것이다. 임의의 모든 시드가 적정 난이도로 완주 가능하거나 최종 밸런스가 완성되었다는 의미는 아니다.

- 미리보기 계약 테스트에 적 방어 변화와 경고 배열 검증을 추가했다.

### Seeded Gameplay QA

- 판정: **PASS**, MVP 차단 결함 없음.
- 동일 시드 상태·이벤트 재현, 잠금 유지, 재굴림 저주 비용, 저주 임계치, 승패 후 명령 차단, 새 런 초기화, 미리보기 무변이성을 확인했다.

- 확인된 강점:

- 후속 제안:

  - 720px 높이에서 수직 구성 수동 점검
  - `prefers-reduced-motion` 회귀 검증

### 레벨 디자인 리뷰

리뷰어는 아래 두 건을 데모 전 실험이 필요한 높은 우선순위로 분류했다. 기술적 시연은 가능하지만 핵심 위험-보상과 난이도 곡선을 설명할 때 주의가 필요하다.

1. **잠금 후 즉시 확정하는 저위험 전략**
   - 대표 플레이의 전투 해결 16회 중 잠금 13회, 실제 재굴림은 4회였다.
   - 일부 전투에서는 잠근 뒤 재굴림 없이 확정해 잠금 연계 보상을 얻었다.
   - 제안 실험: 잠금 보상의 조건을 실제 재굴림과 결합하거나 잠금 확정에 명시적 비용을 부여한다.

2. **중반 자해 절벽과 역전된 조우 난이도**
   - 스테이지 5의 `bullet/all/x3` 결과가 큰 자해를 만들어 HP가 26에서 2로 감소한다.
   - 그 직후 엘리트가 피해 없이 한 턴에 끝나 일반전과 엘리트의 위협 순서가 뒤집혀 보인다.
   - 제안 실험: `all` 대상 추가타의 자기 피해 복제를 제한하는 변형과 대표 시드 교체 변형을 비교한다.

3. **보스 2페이즈 체류 시간** — 포스트 MVP 후보
   - 현재 대표 경로에서는 2페이즈에서 플레이어가 내리는 결정이 사실상 한 번이다.
   - 제안 실험: 2페이즈 최소 생존 게이트 또는 유효 체력을 조정해 2~3회 전투 해결을 노출한다.

이 세 항목은 아직 `Proposed` 상태이며 코드에 반영하지 않았다.

## Landmine 사용 결과

Landmine `0.1.0a3`는 공유 게임 계약을 변경하기 전 **읽기 전용 사전 점검**으로 사용했다.

- `GameEngine` 심볼 점검에서 중복 엔진 후보와 `ambiguous_symbol` 위험을 확인했다.
- 명시적 파일 경로로 다시 점검해 실제 구현 대상이 `src/game/engine/GameEngine.ts`임을 고정했다.
- 최종 점검 ID `lm_27533a68ee3b`, `lm_ea29c0322425`는 모두 `analysis_status: partial`이었다.
- 직접 importer와 테스트 범위를 좁히는 데는 유용했지만, TypeScript 별칭, 동적 경로, 2단계 호출 그래프와 실제 React 런타임 연결은 증명하지 못했다.
- 따라서 Landmine의 낮은 위험 요약을 변경 승인으로 취급하지 않고, 설계 문서·수동 코드 추적·결정론 테스트와 브라우저 검증을 최종 근거로 사용했다.

## 스킬 사용 결과

### 구현과 검증을 도운 스킬 및 도구

- `mvp-contract-auditor`: 단일 결과 소유 엔진, UI RNG 부재, 전투/증강 슬롯 분리, 데이터 기반 콘텐츠 경계를 점검했다.
- `command-trace-recorder`: 대표 시드와 81개 명령을 두 번 재생해 정규화된 상태·이벤트 추적과 다이제스트를 만들었다.
- `content-catalog-linter`: 13개 보상, 3개 시너지, 8,192개 조합을 점검해 ID, 효과, 도달 가능성과 요구 조건을 검증했다.
- `playable-checkpoint-preflight`: 고정 커밋, 실행 명령, URL, 대표 시드, 브라우저 오류와 알려진 한계를 기준으로 리뷰 준비도를 판단했다.
- `seeded-gameplay-qa`: 결정론, 명령 계약과 대표 시드 회귀를 독립 검증했다.
- `slot-ux-review`: 전투 정보 전달, 접근성 및 1280×720 가독성을 검토했다.
- `slot-level-designer`: 대표 시드의 페이싱, 위험-보상, 조우 곡선과 보스 클라이맥스를 검토했다.

### 확인된 한계

- 리뷰 스킬은 플레이 가능한 고정 커밋 이후에만 의미 있는 증거를 낼 수 있어 초기 구현을 대신하지 못한다.
- 단일 대표 시드는 회귀와 시연에는 적합하지만 전체 밸런스 분포의 근거가 아니다.
- 브라우저 자동 클릭은 수동 플레이의 시선 이동, 이해 속도와 수직 스크롤 부담을 완전히 평가하지 못한다.

## OMX 및 에이전트 피드백 활용 방식

기존 `docs/agent/feedback/`의 OMX/에이전트 피드백 중 사람이 `accepted`로 표시한 항목은 다음처럼 구현 판단에 사용했다.

- 구조 피드백: 중복 엔진을 제거하고 순수 TypeScript 엔진을 정상 플레이의 단일 결과 소유자로 정리했다.
- 콘텐츠 스키마 피드백: 아이템·증강·시너지를 엔진 조건 분기보다 데이터 카탈로그와 효과 정의로 구성했다.
- 파일럿 콘텐츠 피드백: 13개 보상과 3개 시너지의 제한된 MVP 카탈로그를 유지했다.
- 스테이지 흐름 피드백: 15스테이지 경로와 5~7스테이지 첫 시너지 완성 목표를 반영했다. 대표 경로는 스테이지 6에 `Clockwork Barrage`를 완성한다.
- UI-엔진 연결 피드백: 당시 제안된 어댑터는 과도기 피드백으로 참고했지만, 최종 구현은 중복 권한을 없애기 위해 React가 정규 `GameEngine` 상태를 표시하고 명령만 전달하도록 정리했다.

최신 OMX 역할 기반 코드 리뷰는 저주 경고 타이밍과 E2E 화면 검증의 모호함을 찾아냈고, 두 항목은 규칙 변경 없이 명확화 및 회귀 강화로 반영했다. 반면 최신 레벨·UX 제안은 아직 사람이 수락하지 않았으므로 자동으로 구현하지 않았다.

## 알려진 한계

- 모든 임의 시드의 완주 가능성과 밸런스는 보장하지 않는다.
- 잠금 보상 우회와 중반 난이도 역전은 인간 결정이 필요한 미해결 디자인 제안이다.
- 접근성 전체 회귀, 텍스트 대비, 현지화와 720px 수직 구성은 후속 검토 대상이다.
- 레거시 미사용 UI 모듈 정리는 이번 MVP 범위에 포함하지 않았다.
